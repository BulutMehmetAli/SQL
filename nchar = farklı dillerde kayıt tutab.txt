Joins:

SQL Joins are used to combine data from two or more tables based on a related column.

Matching records using common columns.
Improving data analysis by combining related information.
Creating meaningful result sets from separate tables.

1. INNER JOIN
INNER JOIN is used to retrieve rows where matching values exist in both tables. It helps in:

Combining records based on a related column.
Returning only matching rows from both tables.
Excluding non-matching data from the result set.
Ensuring accurate data relationships between tables.

SELECT A.column1, A.column2, B.column1, ...
FROM tableA AS A
INNER JOIN tableB AS B
ON A.matching_column = B.matching_column;

Note: We can also write JOIN instead of INNER JOIN.  JOIN is same as INNER JOIN. 

2. LEFT JOIN

In SQL, the LEFT JOIN (also called LEFT OUTER JOIN) retrieves all records from the left table and only the matching records from the right table. If no match is found, NULL values are returned for the right table columns.

SELECT A.column1, A.column2, B.column1, ...
FROM tableA AS A
LEFT JOIN tableB AS B
ON A.matching_column = B.matching_column;

SQL LEFT JOIN with WHERE Clause

In this example, the WHERE clause filters the results to display only employee whose department location is 'London'. departments without employee will not appear in the output.

SELECT e.emp_id,
       e.name,
       d.department_name,
       d.department_head,
       d.location
FROM employee AS e
LEFT JOIN department AS d
    ON e.department_id = d.department_id
WHERE d.location = 'London';

3. RIGHT JOIN

In SQL, the RIGHT JOIN (also called RIGHT OUTER JOIN) is used to combine rows from two tables based on a related column. It returns all records from the right table and only the matching records from the left table. If there is no match in the left table, the result will show NULL values for the left table’s columns.

SELECT A.column1, A.column2, B.column1, ...
FROM tableA AS A
RIGHT JOIN tableB AS B
ON A.matching_column = B.matching_column;

Applications of SQL RIGHT JOIN
Merging Data: Combines related data from different tables.
Ensuring Completeness: Guarantees all records from the right table are included.
Handling Missing Values: Identifies records without matches in the left table.
Analyzing Relationships: Helps detect data gaps and dependencies across tables.

4. FULL JOIN

The FULL JOIN (or FULL OUTER JOIN) in SQL returns all rows from both tables, combining matched rows and filling unmatched rows with NULL values. It is basically the combination of LEFT JOIN and RIGHT JOIN.

SELECT A.column1, A.column2, B.column1, ...
FROM tableA AS A
FULL JOIN tableB AS B
ON A.matching_column = B.matching_column;


Her JOIN türünü, hangi soruyu cevapladığına göre düşünmek en kolayı. Örneklerde senin tablolarını kullanıyorum.

**1. INNER JOIN: "Sadece iki tarafta da olanlar"**

İki tabloda eşleşen satırları getirir, eşleşmeyenleri atar. **En çok kullanılan JOIN budur.**

**Ne zaman:** İki tarafın da bilgisine ihtiyacın varsa ve eşleşmeyen kayıtlar seni ilgilendirmiyorsa.

```sql
-- Harcama yapan öğrencilerin adları ve toplam harcamaları
SELECT Si.StudentName, SUM(Ce.ExpenseAmount) AS Total
FROM StudentInformation Si
INNER JOIN CanteenExpenses Ce ON Si.StudentNumber = Ce.StudentNumber
GROUP BY Si.StudentNumber, Si.StudentName;
```

Sonuç 50 öğrenci. Hiç harcama yapmamış 150 öğrenci gelmez.

**2. LEFT JOIN: "Soldakilerin hepsi, sağdan eşleşen varsa"**

Soldaki tablonun bütün satırlarını getirir. Sağda karşılığı yoksa o kolonlar `NULL` olur. **İkinci en çok kullanılan JOIN.**

**Ne zaman:** Ana listen soldaysa ve hiçbir kaydı kaybetmek istemiyorsan.

```sql
-- Bütün öğrenciler ve toplam harcamaları (harcaması olmayanlar 0)
SELECT Si.StudentName, ISNULL(SUM(Ce.ExpenseAmount), 0) AS Total
FROM StudentInformation Si
LEFT JOIN CanteenExpenses Ce ON Si.StudentNumber = Ce.StudentNumber
GROUP BY Si.StudentNumber, Si.StudentName;
```

Sonuç 200 öğrenci.

**Çok kullanılan bir kalıp, "hiç ... yapmayanları bul":**

```sql
-- Hiç kantin alışverişi yapmamış öğrenciler
SELECT Si.StudentNumber, Si.StudentName
FROM StudentInformation Si
LEFT JOIN CanteenExpenses Ce ON Si.StudentNumber = Ce.StudentNumber
WHERE Ce.StudentNumber IS NULL;
```

Hiç sipariş vermemiş müşteriler, hiç giriş yapmamış kullanıcılar gibi sorular hep bu kalıpla çözülür. Mülakatlarda da çok sorulur.

**3. RIGHT JOIN: LEFT JOIN'in tersi**

Sağdaki tablonun bütün satırlarını getirir. Pratikte nadiren kullanılır, çünkü tabloların yerini değiştirip LEFT JOIN yazmak daha okunaklı. Çoğu ekip sadece LEFT JOIN kullanır.

**4. FULL OUTER JOIN: "İki tarafın hepsi"**

İki tablodaki bütün satırları getirir, eşleşmeyenlerin eksik tarafını `NULL` bırakır.

**Ne zaman:** İki listeyi karşılaştırıp her iki taraftaki eksikleri bulmak istediğinde. Örneğin muhasebe sistemiyle satış sistemindeki kayıtları karşılaştırmak ya da iki tablonun tutarlı olup olmadığını kontrol etmek.

```sql
-- Öğrenci kaydı olup adresi olmayanlar + adresi olup öğrenci kaydı olmayanlar
SELECT Si.StudentNumber, Sa.StudentNumber
FROM StudentInformation Si
FULL OUTER JOIN StudentAddress Sa ON Si.StudentNumber = Sa.StudentNumber
WHERE Si.StudentNumber IS NULL OR Sa.StudentNumber IS NULL;
```

**5. CROSS JOIN: "Her şey her şeyle"**

Eşleştirme koşulu yoktur. Soldaki her satırı sağdaki her satırla birleştirir; 200 × 200 = 40.000 satır çıkar.

**Ne zaman:** Bütün kombinasyonları üretmek istediğinde. Örneğin her mağaza × her ay tablosu oluşturup satış olmayan ayları da 0 olarak göstermek için. Nadiren kullanılır ve yanlışlıkla kullanırsan tablo devasa olur.

**6. SELF JOIN: Tabloyu kendisiyle birleştirmek**

Ayrı bir komut değil; aynı tabloya iki farklı takma ad verip JOIN yapıyorsun.

**Ne zaman:** Aynı tablodaki satırları karşılaştırmak istediğinde. Örneğin aynı gün kayıt olmuş öğrenci çiftlerini bulmak ya da çalışan tablosunda her çalışanın yöneticisini bulmak (yönetici de aynı tabloda bir çalışan).

```sql
-- Aynı gün kayıt olmuş öğrenci çiftleri
SELECT A.StudentName, B.StudentName, A.RecordDate
FROM StudentInformation A
INNER JOIN StudentInformation B
    ON A.RecordDate = B.RecordDate
   AND A.StudentNumber < B.StudentNumber;
```

`<` koşulu, aynı çiftin iki kez (A-B ve B-A) gelmesini ve öğrencinin kendisiyle eşleşmesini engelliyor.

**Özet**

| JOIN | Soru | Kullanım sıklığı |
| INNER | Sadece eşleşenler | Çok sık |
| LEFT | Ana listenin hepsi + varsa ek bilgi | Çok sık |
| RIGHT | LEFT'in tersi | Nadir |
| FULL OUTER | İki listeyi karşılaştırma | Ara sıra |
| CROSS | Bütün kombinasyonlar | Nadir |
| SELF | Tablo içi karşılaştırma | Ara sıra |

SQL Natural Join

Natural Join is a type of join that automatically matches and combines rows from two tables based on columns with same name and compatible data types. Unlike other joins, you don’t need to manually specify condition; SQL detects common columns and returns a result without redundant duplicate columns.

SELECT * 
FROM table1
NATURAL JOIN table2;

Inner Join vs Outer Join

A Join in SQL is used to combine rows from two or more tables based on a related column between them. It allows you to fetch meaningful information by linking data stored across multiple tables in a relational database. The two types of joins are Inner Join and Outer Join.

Inner Join/Simple Join
An Inner Join returns only the matching rows between the two tables based on a specified condition. It combines data from two tables based on a common column between them, which is specified using the ON keyword in SQL. If a row in one table does not have a matching row in the other table, that row will not be included in the result set. In an Inner join, it allows retrieving data from two tables with the same ID.
Inner Join is basically performed by just selecting the records having the common values or the matching values in both tables. In case of no common values, no data is shown in the output.

Outer Join
An Outer Join returns all the rows from one table and matching rows from the other table based on a specified condition. It combines data from two tables based on a common column between them, which is also specified using the ON keyword in SQL. In addition to the matching rows, it also includes rows from one table that do not have matching rows in the other table.

1. Left Outer join 

Left Outer Join returns all rows of a table on the left side of the jorows for which there is no matching row on the right side, the result contains NULL on the right side.
Left Outer Join returns all the rows from the left table and matching rows from the right table. If a row in the left table does not have a matching row in the right table, the result set will include NULL values for the columns in the right table.

2. Right Outer Join 

Right Outer Join is similar to Left Outer Join (Right replaces Left everywhere). Right Outer Join returns all the rows from the right table and matching rows from the left table. If a row in the right table does not have a matching row in the left table, the result set will include NULL values for the columns in the left table.

3. Full Outer Join 

Full Outer Join contains the results of both the Left and Right outer joins. It will provide a mixture of two tables. Full Outer Join returns all the rows from both tables, including matching and non-matching rows. If a row in one table does not have a matching row in the other table, the result set will include NULL values for the columns in the table that do not have a match.

FULL OUTER JOIN, iki tablodaki bütün satırları getirir. Eşleşenleri yan yana koyar. Eşleşmeyenleri de atmaz; eksik tarafı NULL ile doldurarak sonuca ekler.

Kısaca: FULL OUTER JOIN = LEFT JOIN + RIGHT JOIN’in birleşimi.

FULL OUTER JOIN çaprazlama yapmaz. Çaprazlamayı CROSS JOIN yapar.

Ama dikkat etmen gereken bir “çoğalma” durumu var. Bu sadece FULL JOIN’e özgü değil, bütün JOIN’lerde olur. Eşleştirdiğin kolonda bir değer iki tarafta da birden fazla kez geçiyorsa, o değer için satırlar çarpılır.

Örnek: bir öğrencinin kantin tablosunda 3 işlemi, adres tablosunda da 2 adresi olsaydı:

CanteenExpenses: 2020015 → 20, 30, 10     (3 satır)
StudentAddress:  2020015 → Adres A, Adres B (2 satır)

JOIN sonucunda bu öğrenci için 3 × 2 = 6 satır çıkar. Her harcama her adresle eşleşir. Bu bir tür kontrollü çaprazlama ve en tehlikeli yanı toplamları bozması: SUM(ExpenseAmount) 60 yerine 120 çıkar, çünkü her harcama iki kez sayılır.

Bizim tablolarda bu sorun var mı?

StudentInformation ve StudentAddress’te her öğrenci numarası bir kez geçiyor. Bu yüzden önceki sorgular güvenli; çoğalma yok.
CanteenExpenses’ta bir öğrenci birden fazla kez geçiyor (bire-çok ilişki). Bu normal; sonuçta her harcama için bir satır olur, çoğalma değil.
Önceki mesajdaki 4. örnekte (üç tablo birden) toplam doğru çıkıyor, çünkü adres tablosunda her öğrenci tek. Bir öğrencinin iki adresi olsaydı, harcaması iki kez sayılırdı.

Pratik kural: JOIN’den sonra satır sayısı beklediğinden fazlaysa, eşleştirdiğin kolonda tekrar eden değerler vardır. Kontrol etmek için:

SELECT StudentNumber, COUNT(*)
FROM StudentAddress
GROUP BY StudentNumber
HAVING COUNT(*) > 1;   -- boş dönerse tekrar yok

“JOIN’den sonra rakamlar şişti” hatası çok sık yaşanır sebebi nedir ?

“Hayır, FULL OUTER JOIN çaprazlama yapmaz. Çaprazlama yani kartezyen çarpım CROSS JOIN’dir; eşleştirme koşulu olmadan her satırı diğer tablodaki her satırla birleştirir. FULL OUTER JOIN ise ON koşuluna göre eşleşen satırları yan yana getirir, iki taraftaki eşleşmeyen satırları da eksik kolonları NULL olacak şekilde sonuca ekler. Ancak şuna dikkat etmek gerekir: eşleştirme kolonunda bir değer iki tabloda da birden fazla kez geçiyorsa, o değer için satırlar çarpılır ve toplamlar şişer. Bu yüzden JOIN’den önce anahtar kolonun benzersiz olup olmadığını kontrol ederim, JOIN’den sonra da satır sayısının beklentiyle uyuştuğuna bakarım.”

"Eşleştirme kolonu", `ON` kısmında kullandığın kolon. Bizim örneklerde bu `StudentNumber`. İfade şunu anlatıyor: aynı öğrenci numarası **her iki tabloda da** birden fazla satırda geçiyorsa sorun çıkar.

Üç durumu karşılaştıralım:

**1. Bire-bir: iki tabloda da bir kez geçiyor → sorun yok**

```
StudentInformation        StudentAddress
2020015 | Ali             2020015 | Adres A
```

Sonuç: 1 × 1 = **1 satır**. Bizim StudentInformation ile StudentAddress tabloları böyle.

**2. Bire-çok: bir tabloda bir kez, diğerinde çok kez → normal**

```
StudentInformation        CanteenExpenses
2020015 | Ali             2020015 | 20
                          2020015 | 30
                          2020015 | 10
```

Sonuç: 1 × 3 = **3 satır**. Her harcama için bir satır geliyor ve bu zaten istenen şey. Ali'nin adı üç kez tekrar etse de toplam harcama doğru çıkıyor: 60.

**3. Çoka-çok: iki tabloda da birden fazla kez geçiyor → çoğalma**

Diyelim ki Ali'nin adres tablosunda iki kaydı var (ev ve yurt adresi) ve kantinde 3 işlemi var:

```
StudentAddress            CanteenExpenses
2020015 | Ev              2020015 | 20
2020015 | Yurt            2020015 | 30
                          2020015 | 10
```

Bu iki tabloyu `StudentNumber` üzerinden JOIN'lediğinde SQL her adresi her harcamayla eşleştirir:

| Adres | Harcama |
|---|---|
| Ev | 20 |
| Ev | 30 |
| Ev | 10 |
| Yurt | 20 |
| Yurt | 30 |
| Yurt | 10 |

Sonuç: 2 × 3 = **6 satır**. Burada sorun şu: `SUM(Harcama)` hesaplarsan **120** çıkar, ama Ali aslında **60** TL harcadı. Her harcama, adres sayısı kadar (2 kez) sayılmış oluyor.

**Neden önemli?** Gerçek veritabanlarında bu çok sık oluyor. Bir müşterinin birden fazla adresi, telefonu ya da kampanya kaydı olabiliyor. Bunu fark etmeden JOIN yapıp toplam alırsan ciroyu, müşteri sayısını veya harcamayı olduğundan fazla raporlarsın, ve hata kimsenin gözüne çarpmadan bir yönetici raporuna kadar gidebilir.

**Nasıl önlenir?**
- JOIN'den önce eşleştirme kolonunda tekrar olup olmadığını kontrol et (`GROUP BY ... HAVING COUNT(*) > 1`).

SELECT StudentNumber, COUNT(*)
FROM StudentAddress
GROUP BY StudentNumber
HAVING COUNT(*) > 1;   -- boş dönerse tekrar yok

- Toplamları **JOIN'den önce** ayrı ayrı hesapla, sonra birleştir:

```sql
SELECT Si.StudentName, T.TotalExpense
FROM StudentInformation Si
INNER JOIN (
    SELECT StudentNumber, SUM(ExpenseAmount) AS TotalExpense
    FROM CanteenExpenses
    GROUP BY StudentNumber
) T ON Si.StudentNumber = T.StudentNumber;
```

Burada harcamalar önce öğrenci başına tek satıra indiriliyor. Sonrasında hangi tabloyla JOIN yapılırsa yapılsın toplam çoğalmıyor.

How To Use Outer Join
Outer Join is performed by the selection of the records from all the tables given there. Left Outer Join works by selecting all records from the left table and matching records from the right table. Similarly, Right Outer Join works by selecting all records from the right table and matching records from the left table and the Full Outer Join returns all records if a match occurs in the left or the right table.

Advantages
Increased Data Retrieval: Outer joins can retrieve more data than inner joins since they include non-matching rows in the result set.
Data Integrity: Outer joins can help maintain data integrity by ensuring that all records in the primary table are returned, even if there are no corresponding records in the secondary table.
Data Analysis: Outer joins can be useful for data analysis, especially when exploring relationships between data sets and identifying trends and patterns.
Disadvantages
Slow Query Execution: Outer joins can be slower to execute than inner joins, especially when dealing with large data sets.
Data Duplication: Outer joins can return duplicate data when the secondary table has multiple matching records.
Data Quality: Outer joins may return inaccurate or incomplete data if the tables being joined have incomplete or inconsistent data.
